Nothing is kept.

pdfyier converts your images and sends the PDF straight back to your browser. Nothing about the process is designed to keep a copy.

Held in memory, never on disk.
Your images live only in RAM-backed temporary storage for the few seconds it takes to build your PDF. The moment your download starts, that memory is cleared, on the server and inside the container that runs the conversion.
Logged like any website, and no more.
Standard server logs record your IP address, the time of the request, and the response status. Never filenames, file contents, or anything from inside your upload.
No third parties. No accounts.
Conversion happens entirely on our own server, and your files are never sent anywhere else. There’s no sign-in, and no tracking cookies.

How it works.

One request, start to finish. Your images go up, a PDF comes back, and the temporary files are deleted in between.

  1. Your browserSends your images, in your order.
  2. nginxDecrypts HTTPS and turns away uploads over 150 MB.
  3. FastAPIChecks each file and holds it in RAM-backed storage.
  4. ImageMagickDraws each image onto its own PDF page.
  5. Back to youTemp files are deleted and the PDF streams back.
Every step, in detail

  1. Your browser collects the images

    The page keeps your files in an items list, in whatever order you set by dragging.

  2. Create PDF packages and sends them

    An HTTPS POST with multipart/form-data, each image a separate part of the body.

    const formData = new FormData();
items.forEach(it => formData.append('files', it.file));
xhr.open('POST', `${API_URL}/convert`);
xhr.send(formData);

  3. nginx receives the request

    Terminates TLS (decrypts the HTTPS traffic), checks client_max_body_size (150M) and rejects anything larger with a 413, then proxies the request to the FastAPI container on localhost:8000.

  4. FastAPI (main.py) receives it

    For each file, in order: checks the extension against ALLOWED_EXTENSIONS, reads the bytes into memory, checks the per-file size and running total, then writes the bytes to a RAM-backed temp file. A numbered prefix keeps page order regardless of the original filenames.

    async def convert(files: list[UploadFile]):

  5. ImageMagick does the conversion

    The magick CLI reads and decodes each image, turns it upright using its orientation data, renders each one onto its own PDF page in order, and writes the multi-page PDF into the same temp directory.

    cmd = ["magick", *paths, "-auto-orient", output_path]
subprocess.run(cmd, ...)

  6. FastAPI reads the result into memory

    Then the temp directory context exits, and the whole folder, original images and PDF included, is deleted immediately.

    with open(output_path, "rb") as f:
    pdf_bytes = f.read()

  7. The response streams back

    It travels back through nginx, re-encrypted over HTTPS, to your browser.

    return Response(content=pdf_bytes, media_type="application/pdf", ...)

  8. Your browser saves the file

    The page makes a temporary in-browser object URL and clicks a download link with your chosen file name. The URL is released when you change the pages or clear them.

    pdfUrl = URL.createObjectURL(xhr.response);
a.download = sanitizeFilename(filenameInput.value) + '.pdf';
a.click();

The one-line version

upload → nginx (TLS + size check) → FastAPI (validate + save to tmpfs)
       → magick CLI (decode images → render PDF pages) → FastAPI reads result
       → temp files deleted → PDF streamed back → browser downloads it

Everything from step 4 to step 6 happens inside a single HTTP request and response. Nothing persists before or after.

Help.

How do I add images?

Click Choose Images, or drag images from your computer anywhere onto the page. You can also paste a copied image with ⌘V or Ctrl+V.

How do I change the page order?

Drag any page to a new spot. On a phone, touch and hold a page, then drag. With a keyboard, focus a page, press Space to pick it up, use the arrow keys, and press Space to drop it. The number on each page is its position in the PDF.

Can I rename the download?

Yes. Use the File name field next to Create PDF. It always saves as a .pdf.

What file types are supported?

JPG, PNG, WEBP, BMP, TIFF, and GIF, up to 20 MB each. HEIC photos from an iPhone aren’t supported, so export them as JPG first.

Why did my upload fail?

Usually one of: a file over the size limit, an unsupported format, or too many conversions in a short time. Wait a moment and try again.

Is there a limit on file count?

Up to 50 images per PDF, 150 MB combined.
